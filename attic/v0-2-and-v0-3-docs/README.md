# Atticked v0.2.0 / v0.3.0-era planning & status docs

These 15 markdown files documented the v0.2.0–v0.3.0 development cycle:
version-pinned status reports, roadmaps, stabilization/strategy planning,
early-adopter comms, and one-off compilation-fix logs. They described work
and timelines that are long completed or superseded, yet sat in `docs/`
where new users saw them — rot that signals a lack of stewardship.

Per the v0.11.0 doc-consolidation pass (#232), they are preserved here
rather than deleted, following the v0.10.0 #177 / #180 attic pattern.

Removed-subsystem roadmap:
- `access_control_roadmap.md` — the RBAC/access-control subsystem it

## Why attic instead of delete

These are historical artifacts of how the project evolved. Keeping them
out of `docs/` removes the rot from the user-facing tree while preserving
the history for anyone tracing past decisions. Current roadmap and
planning live in `docs/plans/` and the issue tracker.
